## Building and running

Visual Studio 2022 is the primary development environment; mixed Python/native debugging
(stepping from a Python script into a C++ item's `ComputeODE2LHS`) is the project's most valuable
capability and is protected by design.

- **IDE**: run `python tools/setupLocalWorkspace.py` once, then open the `exudyn.sln` it
  creates and build `Debug|x64` or `Release|x64`. That solution and `python/pytest.py` are
  untracked scratch copies of committed templates, so experiments cannot be committed.
- **Wheel**: `main/setup.py`, about one minute. Also protected by design.
- **Scripts**: one driver, `exudev` - `exudev --help`, and `exudev -n <command>` to see what a
  command would run. Its commands are listed in [`tools/exudev/README.md`](../../tools/exudev/README.md).
- **Tests**: `runTestSuite.py` from `python/testing/`, about 20 s. Run it in full.

Entry points worth knowing:

- `src/Pymodules/PybindModule.cpp` — module creation.
- `src/Main/MainObjectFactory.h/.cpp` — item creation behind `mbs.AddNode(...)`; dispatch is
  on the `objectType` **string** from the Python dict, through a runtime class-factory registry.

## Invariants

These are differentiators, not technical debt. Every restructuring step preserves them
(plan §7):

- VS2022 as primary development environment, with mixed Python/native debugging.
- The setuptools-based fast build.
- No heavy C++ dependencies; vendored headers.
- The hard C++/Python split with dict-based validated interfaces.
- Runtime dependencies stay at numpy only. Development-only tools are unconstrained.
