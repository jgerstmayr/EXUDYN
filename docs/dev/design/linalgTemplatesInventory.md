# The linear algebra function templates: inventory and consolidation (design note)

An inventory of the free functions and member helpers that multiply and add matrices and vectors in `src/Linalg`
(`namespace EXUmath` in `Matrix.h` and `BasicLinalg.h`, the members of `MatrixBase`, the fixed-size operators), with
their call sites, duplicates, dead ones and performance notes, and a proposal to consolidate them. It complements
[linalgFixedSize.md](linalgFixedSize.md) (compile-time sizes, `SlimMatrix`, #3456),
[linalgBenchmark.md](linalgBenchmark.md) (L1-L6, #3417-#3419) and [expressionTemplates.md](expressionTemplates.md).

The counts and line numbers were taken with `Matrix3D` as `ConstSizeMatrix<9>`; `Matrix6D` and `Matrix3D` are now
`SlimMatrix<6,6>` and `SlimMatrix<3,3>` (#3458, #3459, #3467); what is said here of `Matrix3D` as
`ConstSizeMatrix<9>` still holds for `Matrix3DF` and for the other `ConstSizeMatrix` sizes.

Call sites are word counts over `src/` (2026-11-12), **without the definition files** (`Matrix.h`, `BasicLinalg.h`) and
without comment-only lines where checked by hand; `src/Tests` and `linalgBenchmark.h` are listed separately where they
matter. `src/Autogenerated` calls none of these functions (only `CopyFrom`, 9 times).

### 5.2 Duplicates

- **Set and add variants of the same product** are four pairs of near-identical kernels: `MultMatrixVector` /
  `...Add`, `MultMatrixTransposedVector` / `...Add`, `MultMatrixMatrix` / `...Add` (dead), `MultMatrixTransposedMatrix` /
  `...Add`. They differ in three lines (resize or check, `=` or `+=`) and have drifted apart: the set variant of the
  transposed matrix product is rank-1 (L3), the add variant an inner product; the transposed vector kernels are
  `Real`-only while the plain one is generic.
- **`MultMatrixMatrix2SubmatrixTemplate`** is `MultMatrixMatrixTemplate` writing into a block, with checked access
  instead of `GetUnsafe`.
- **`AddSubmatrixTransposed` (`Matrix.h:990`) and `AddTransposedSubmatrix` (`:1087`)** are the same operation.
- **`AddSubmatrix` and `AddSubmatrixWithFactor`**, `AddSubmatrixTransposed` and `...WithFactor`: `SetSubmatrix` already has
  the factor as a defaulted last argument; `1.*x == x` exactly, so one function with `factor = 1.` gives the same bits.
- **`FactorTimesMatrixAddTemplate`** is `AddSubmatrix(m, 0, 0, factor)` for a matrix of the same shape, and is what
  `MultAdd` is for vectors.
- **`AddColumnVectorDiff` / `SetColumnVectorDiff`**: a set/add pair (kept; small).
- **Two naming schemes for one operation**: `EXUmath::MultMatrixTransposedMatrixTemplate(m1, m2, r)` (output argument) and
  `MultTransposedMatrix(m1, m2)` (`SlimMatrix.h:482`, returns); `v * A` (`ConstSizeMatrix.h:1061`, `SlimMatrix.h:519`)
  and `MultTransposedVector`.
- **The 33 wrappers** of §2 duplicate the deduction of the templates.

What is known and what is estimated: the kernels with pointer loops (L1, L3) gained 2-5 times over checked or strided
access at n = 6-24 (linalgBenchmark.md §3.6). `MultMatrixMatrix2SubmatrixTemplate` has the access pattern those kernels
had before; its gain is **estimated** at 2-3 times in the regular module and less in the fast one (no checks there). For
the connector Jacobian of a rigid pair with Euler parameters, four blocks of 7x6 times 6x7 (294 multiply-adds each) -
roughly 1-2 us of the about 10 us per connector and Jacobian (§3.7): a gain of 5-15 % of that Jacobian, to be measured
(benchmark case in §7).

### 5.4 Interplay with compile-time sizes

`SlimMatrix` has `static constexpr NumberOfRows()/NumberOfColumns()` (`SlimMatrix.h:130-131`), so the `EXUmath`
kernels accept it; since the kernels copy the sizes into locals, an inlined call on `SlimMatrix` arguments sees constant
trip counts. The consolidated kernels must keep that: sizes read once into `const Index` locals, no virtual calls, no
member access like `sm.numberOfRows` that only `MatrixBase` has.

## 6. Consolidation

### 6.1 Target: four products, three modes, one kernel each

```cpp
namespace EXUmath {
	//! how a kernel writes its result: set (resize to the product), add or subtract (result has the size of the product)
	enum class ResultMode { set, add, subtract };

	//! r = m*v, r += m*v, r -= m*v; each item summed in a local over j = 0, 1, ... from 0, then written once
	template<ResultMode mode = ResultMode::set, class TMatrix, class TVector, class TVectorResult>
	inline void MultMatrixVector(const TMatrix& matrix, const TVector& vector, TVectorResult& result);

	//! r = m^T*v (and add, subtract); the element type is the result's (Real or AutoDiff)
	template<ResultMode mode = ResultMode::set, class TMatrix, class TVector, class TVectorResult>
	inline void MultMatrixTransposedVector(const TMatrix& matrix, const TVector& vector, TVectorResult& result);

	//! R = m1*m2 (and add, subtract); set: axpy over the rows of R (each entry summed over k from 0);
	//! add/subtract: each entry in a local, applied once
	template<ResultMode mode = ResultMode::set, class TMatrix1, class TMatrix2, class TMatrixResult>
	inline void MultMatrixMatrix(const TMatrix1& m1, const TMatrix2& m2, TMatrixResult& result);

	//! the block of result at (row, column) = m1*m2 (and add); result keeps its size
	template<ResultMode mode = ResultMode::set, class TMatrix1, class TMatrix2, class TMatrixResult>
	inline void MultMatrixMatrixToSubmatrix(const TMatrix1& m1, const TMatrix2& m2, TMatrixResult& result, Index row, Index column);

	//! R = m1^T*m2 (and add, subtract); set: rank-1 updates (L3); add/subtract: inner product in a local
	template<ResultMode mode = ResultMode::set, class TMatrix1, class TMatrix2, class TMatrixResult>
	inline void MultMatrixTransposedMatrix(const TMatrix1& m1, const TMatrix2& m2, TMatrixResult& result);
}
```

with the readable add forms as one-line aliases, because `MultMatrixTransposedVectorAdd(J, f, r)` is what the 21 force
projections and a human searching the code expect:

```cpp
template<class TMatrix, class TVector, class TVectorResult>
inline void MultMatrixTransposedVectorAdd(const TMatrix& matrix, const TVector& vector, TVectorResult& result)
{ MultMatrixTransposedVector<ResultMode::add>(matrix, vector, result); }
//MultMatrixVectorAdd, MultMatrixMatrixAdd (if a caller appears), MultMatrixTransposedMatrixAdd alike
```

Each kernel is one function body; the mode is an `if constexpr` at the write (and, for the matrix products, the choice
of the loop form). In the debugger a call steps into one readable loop nest, as today. The `Template` suffix goes: the
plain name is the template, there are no overloads to distinguish it from.

**Bits** - each mode keeps the order of the variant it replaces:

| mode | per entry | equals today's |
|---|---|---|
| set | `value = 0; value += a_k b_k` (k increasing); `r = value` | every set kernel (rank-1 and axpy forms accumulate each entry in the same order from 0) |
| add | `value` as above; `r += value` | `...AddTemplate` kernels (local sum, added once) |
| subtract | `value` as above; `r -= value` | `r += J^T(-f)` and the negated matrix (`CObjectConnector.cpp:90` `localJac *= -1.`): negation is exact, so `r - value` = `r + (-value)` |

An add mode written as axpy directly into the result (`r + a0 b0 + a1 b1 ...`) would change the bits; the kernels must
not do that. `subtract` is optional: it removes the sign flips at the call sites but adds a third branch; only worth it
if the call sites are touched anyway.

### 6.3 What is not merged

- The `GeneralMatrix` / `MatrixContainer` interface (§3, last paragraph): virtual, dense and sparse.
- `AddColumnVectorDiff` / `SetColumnVectorDiff`: used by the numerical Jacobians, small.
- `RigidBodyMath::ApplyTransformation*`, `ApplyTransformation33`: blockwise transformations, a different operation.
- `AddMatrixToSparseTripletVector` (`BasicLinalg.h:733-765`): assembly into triplets.
