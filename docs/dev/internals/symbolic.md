# exudyn.symbolic: how it works inside

How `exudyn.symbolic` (`esym`) records, evaluates, optimizes and writes out expressions, and how a symbolic user
function is set up and called - for whoever changes the C++ or the Python of it. What a user does with it is on the
reference page {ref}`sec-cinterface-symbolic` and in the manual chapter {ref}`sec-symbolicuserfunctions`.

| `src/Linalg/SymbolicVector.h`, `SymbolicMatrix.h` | the vector and matrix nodes, `SymbolicRealVector`, `SymbolicRealMatrix` |
| `src/Linalg/SymbolicUtilities.h` | `SymbolicFunction`, `PySymbolicUserFunction`: the recorded user function, its arguments, its evaluation |

## 1. The recording

**A recording is a graph.** Every operation on symbolic values while `esym.SetRecording(True)` creates one node that
points to its operands; a Python variable used twice points twice to the same node. The nodes are of three kinds,
`ExpressionBase` (a number), `VectorExpressionBase` and `MatrixExpressionBase`; the Python objects `esym.Real`,
`Vector`, `Matrix` are the holders `SReal`, `SymbolicRealVector`, `SymbolicRealMatrix`, each with a pointer to its node
or, without a node, a value.

- **Leaves**: `ExpressionReal` (a number), `ExpressionNamedReal` (a named variable or an argument), and their vector
  and matrix forms `VectorExpressionReal`/`NamedReal`, `MatrixExpressionReal`/`NamedReal`. An argument and a
  variable of `esym.variables` are both named leaves; they differ in who writes them (section 2).
- **Numbers are computed, not recorded**: an operation whose operands are all plain numbers - holders without a node,
  such as `esym.Real(13)` - gives a number. A named variable stays symbolic, as it can change.
- **Reference counting**: a node counts its users. A new operation node has the count 0 and its constructor does not
  reference its operands - the holder or the creating code does. The constructors of the leaves of values
  (`ExpressionReal`, `VectorExpressionReal`, `MatrixExpressionReal`) count one user at once, so code that creates one
  for a user that counts again normalizes with one decrement (`Optimizer::Number`, `NewWithOperands` of
  `VectorExpressionSReal`). A node whose count reaches zero is destroyed, and its `Destroy()` releases its operands,
  recursively. `esym.Real.__newCount - esym.Real.__deleteCount` (and of `Vector`, `Matrix`) is the number of nodes
  that exist; symbolicOptimizeTest.py checks that it returns to its start.
- **The value of a new holder**: `SReal(ExpressionBase*)` evaluates the new node at once, which for a deep graph means
  its whole subtree - the recording of a chain is quadratic in its depth (#3090).
- **Refused while recording**: `float(x)`, `math.sin(x)` and a float array of a symbolic value, which would record a
  constant (#3017); `*` of two vectors or with a matrix and `==` of two vectors, which numpy defines differently
  (#3015, `exudyn.special.deprecations.symbolicStarProduct` for the transition, #3016). The three holder types implement
  numpy's `__array_ufunc__`, so `np.sin(x)` and `K @ q` with a numpy `K` record; `bool(x)` - a Python `if`, `and`,
  `or`, `not` - of an expression or a named variable, which took every symbolic value as true (#3096).

## 2. A symbolic user function

`CreateSymbolicUserFunction(mbs, function, userFunctionName, itemOrNone)` calls the Python function once with named
symbolic arguments - `esym.Real`, `Vector` and `Matrix` named after the parameters, vectors of run-time size with the
size of the coordinates of the item where it is known (#3015) - and builds a dict of `functionName`, `argList`,
`argTypeList`, `argNameList`, `returnValue`, `returnType`. `PySymbolicUserFunction::SetupUserFunction` keeps the dict
(it keeps the recording alive), puts the argument holders into `argRealList` and the result into `returnValue`, and
builds the flat program (section 3). `optimize=True`, the default, applies `esym.Optimize` to the result first
(section 5).

**The call.** `PySymbolicUserFunctionSet.h` (generated from the user function declarations of `definitions/`) sets the
`std::function` of the signature to a lambda that calls `EvaluateReal`, `EvaluateStdVector3D`, ... of the function.
Each of them writes the arguments into the named leaves (`processArgument`, one overload per argument type: a copy
into the memory the leaf keeps, no allocation once the sizes are set, #3006) and evaluates the result. The items that
take vectors or matrices of run-time size call `EvaluateUserFunctionIntoVector`, `EvaluateUserFunctionIntoMatrix` and
`EvaluateUserFunctionIntoMatrixContainer` instead (SymbolicUtilities.h, evaluateUserFunctions.cpp), which evaluate a
symbolic function into the item's own memory without the `std::function`. A matrix result built from components with
constant zeros is sparse: its pattern is fixed when it is recorded and it is evaluated into triplets (#3022).

**Two scopes of variables**: the arguments are local to the function and written by C++ before each call; the
variables of a `VariableSet` (`esym.variables`, `mbs.symbolic.variables`) are global, written by Python between calls
and read by every recording that uses them. A recording writes nothing.

## 3. The evaluation: the flat program

After the recording, `SymbolicFunction::BuildFlatProgram` sorts the graph into a `FlatProgram` (#3053, #3054):

- `Build(roots)` visits the nodes depth first, operands before their operation, with an explicit stack; operation k
  computes slot k. A node used several times is one operation, so it is computed once per call.
- An operation computes its value from the values of its operands: `EvaluateFromOperands(const FlatValue*)`, a
  `FlatValue` per operand holding the number, or the vector or matrix its node evaluated into. The vector and matrix
  nodes evaluate into a buffer of their own (`EvaluateRef`, #3006, #3021) and their slot points to it.
- Nothing is kept from one call to the next: the slots belong to one evaluation (decision D18 of the revision, #3048).
- `NumberOfOperands()`, `GetOperand(i)` and `EvaluateFromOperands` are the operand interface of every node class;
  `IfThenElse` has its three operands, computes both branches and selects by the condition (#3089).
- The text of `GetFlatProgram()` writes one line `tK = ...` per operation; leaves and the components of arguments
  (`InlineInFlatText()`, `q[1]`) are written into their users.
- `flatEvaluation = False` evaluates the recording as a tree instead, recursively, with the same results; it stays as
  the reference of test_symbolicFlatEvaluation.py.

## 4. In the threads of the parallel loops

A recording cannot be evaluated by two threads at once: the arguments are written into its leaves, its slots and the
buffers of its vector and matrix nodes hold the values of one evaluation, and one recording serves many items. So each
thread but the main thread evaluates a **copy** of it (#2978):

- `SymbolicFunction::PrepareThreads(n)` makes the copies of the threads 1 ... n-1 in the order of the flat program:
  each operation new by `NewWithOperands` (section 5), each argument leaf a new named leaf of the same name and value;
  the numbers and the other variables are shared, as an evaluation only reads them. The copy has its own flat program.
- An evaluation takes the copy of `ExuThreading::TaskManager::GetThreadId()`; the main thread, 0, the recording.
  `processArgument` writes into the leaves of the copy; an argument the recording does not use has no leaf there.
- A recording can be copied if every operation of its flat program without operands is a leaf of values; a constant
  result, or a result that is a leaf but no argument, is only read, and its copies have no program
  (`ThreadCopiesPossible`). `CanEvaluateInThreads()` says so.
- Which items are computed in the threads, and when the copies are made, is the rule of
  {ref}`the user functions <sec-dev-userfunctions-threads>`.

## 5. esym.Optimize

`Optimize(expressions, level=1, mergeDuplicates=True)` builds a new graph from an existing one; the input is unchanged,
the parts that do not change are shared (#3085). `class Optimizer` in Symbolic.cpp:

- one pass, operands before their operation, without recursion, with a map from old node to new node;
- for each node, the new operands first, then the rules of the level; if one applies, the result is an operand or a
  number and no node is made;
- with `mergeDuplicates`, a key per node: an operation by its class (`std::type_index`) and the pointers of its new
  operands, the two operands of `+`, `*`, `==`, `!=` sorted; a number and a vector or matrix of numbers by its bits; a
  named variable by its pointer. As the operands are merged first, one level of comparison compares the whole
  subexpression, so `mergeDuplicates` is a bool; equal leaves such as `q[1]` merge too;
- a new node is made by `NewWithOperands(const FlatNode*)` of its class, one line per class;
- the nodes made and not used by the result are freed at the end, in reverse order, each held once more while the
  list is freed, so that no node is deleted by its user before its turn.

| level | rules | result |
|---|---|---|
| 0 | none, only the merging | the same bits |
| 1 | `1*x`, `x*1`, `x/1`, `+x`, `x**1`, `-(-x)` → `x`; `x**0` → `1`; `x+0`, `0+x`, `x-0` → `x`; an operation of numbers → the number, computed by the node's own function; `IfThenElse` of a number condition → its branch; a component of a vector of numbers or of `esym.Vector([a, b, c])` → that component; `M.T.T` → `M` | the same bits, except the sign of a zero sum |
| 2 | also `0*x`, `x*0`, `0/x` → `0`; `x-x` → `0`; `x/x` → `1`; the numbers of products and sums combined, `2*(3*x)` → `6*x` | a `nan` or `inf` of `x` can disappear; the last bit can change |

`CreateSymbolicUserFunction(..., optimize=True)` applies level 1; a dict passes the arguments of Optimize, `False`
keeps the recording as it is. userRigidBodyTest.py has 227 operations instead of 314; a rigid-body force written for
clarity takes 0.15 instead of 0.31 s.

## 6. The recording as data and as code

`GetFlatProgramData()` - of a `UserFunction`, or `esym.GetFlatProgramData(expressions, arguments, resultNames)` - is
the flat program as a Python structure, built in C++ by `FlatProgramData` (#3087). Entry k of `operations` is
operation k, the `tK` of the text; operands are given by their numbers, which are always smaller than k, so a writer is
one loop:

```python
{'arguments':  [{'name': 'x', 'kind': 'Real', 'value': 2.0}, ...],
 'operations': [{'op': 'variable', 'kind': 'Real', 'name': 'x', 'value': 2.0, 'text': 'x', 'inline': True},  # 0
                {'op': 'cos', 'kind': 'Real', 'operands': [0], 'inline': False},                              # 1
                ...],
 'results':    [{'name': 'result', 'kind': 'Real', 'node': 5}]}
```

- Leaves are `'number'` (a value, a list, a list of rows) and `'variable'`; `'text'` is their C++ text. Operations are
  named by `FlatName()` of their class: `+ - * /`, the comparisons, `pos`, `neg`, the functions by their
  exudyn.symbolic names, `IfThenElse`, `vector`, `matrix` (with `rows`, `columns`), `@`, `vector@matrix`, `multiply`,
  `NormL2`, `T`, `component`.
- Of a user function, it adds `name`, the arguments of the Python signature with their type and size (`argNameList`
  of the dict), and `variables`, the named variables of `esym.variables` it reads. Of expressions, the arguments are
  the named variables, in the order given or of their first appearance.

`exudyn.misc.symbolicExport.Write(data, format, flatten, name, expressionOnly)` writes the formats; `ToFunction` and
`ToSympy` give a function and sympy expressions. `GetFlatProgram(format=...)` and `ToString(format=...)` call it,
except for `'Python'`, the text of today, which C++ writes - `Write` gives the same text, so a format can move between
Python and C++ without a change of its result. What a format computes differently is written as Exudyn computes it:

| exudyn.symbolic | `'numpy'` | `'sympy'` |
|---|---|---|
| `mod(x, y)`, C `fmod` | `np.fmod` | `x - y*sign(x/y)*floor(Abs(x/y))` |
| `round(x)`, halves away from zero | `trunc(x) + sign(x)*(abs(x - trunc(x)) >= 0.5)` | `sign(x)*floor(Abs(x) + 1/2)` |
| a comparison, 0 or 1 | `1.0*(x > y)` | `Piecewise((1, Gt(x, y)), (0, True))` |
| `IfThenElse(c, a, b)` | `a if c else b` | `Piecewise((a, Ne(c, 0)), (b, True))` |
| `Not(x)`, `isfinite(x)` | `1.0*(x == 0)`, `1.0*np.isfinite(x)` | `Piecewise`; isfinite refused |
| `@` of two vectors, `v @ M`, `multiply`, `NormL2` | as written | `a.dot(b)`, `M.T @ v`, `multiply_elementwise`, `norm()` |

The format `'symbolic'` reads the variables of `esym.variables` from there, so that the written function keeps the
signature of the user function and records them again; `'numpy'` and `'sympy'` take them as keyword arguments with
their present value. The unary `+` of a vector or matrix and `==`/`!=` of two vectors exist in C++ and in the writer
but cannot be reached from Python. Speed: the C++ text about 4 M entries per second, the structure and the writer
together about 0.7 M (the 300 operations of userRigidBodyTest.py in half a millisecond).

## 7. exudyn.symbolicUtilities

The rotation and kinematics functions of `exudyn.cUtilities` - Skew, Cross, Inertia6D2InertiaTensor, the rotations
about axes, the Tait-Bryan angles xyz and their G matrices, the Euler parameters, the rotation vector, 21 in all - with
the names and arguments of cUtilities and a last argument `functions` (#3069):

- inside, only the names that `exudyn.symbolic`, `exudyn.cMath`, `math` and `numpy` share: `sin`, `cos`, `tan`,
  `asin`, `acos`, `atan`, `atan2`, `sqrt`, `exp`, `log`, `pow`, and `pi` (`esym.pi`, #3071);
- the result follows `functions`: a symbolic matrix or vector for `exudyn.symbolic`, a numpy array for the others; the
  private helpers `_Matrix` and `_Vector` make it;
- a branch - only the small-angle case of RotationVector2RotationMatrix - is `IfThenElse` when the angle is symbolic,
  a Python `if` otherwise;
- not in it: the inverse conversions (RotationMatrix2...) and LogSO3, whose branches select by the largest component,
  the orthonormal bases, SymmetricBasis, the HT and T66 functions.

For numbers alone, cUtilities stays the fast way (0.63 us against 1.2 to 2.4 us for one RotXYZ2RotationMatrix).

## 8. What it does not do

| | | |
|---|---|---|
| a recording deeper than about 34000 nested nodes | overflows the 2 MB stack of python.exe while recording or in `Evaluate`; `Diff` at 28000, `str()` at 9000; the flat program, the structure and Optimize do not recurse | #3090 |
| the MainSystem in an expression | `mbs.GetNodeOutput(...)` inside a recorded function is a constant | #2984 |
| derivatives | `Diff` of scalars only, a number: the forward derivative at the current values | - |
| matrix functions | no inverse, no product of the components of matrices; vectors have `esym.cross` (#3070) | - |
| constant matrix arguments | copied into the named matrices at every call | #3039 |

## 9. Decisions

| decision | why |
|---|---|
| flat evaluation, values per evaluation only (#3048, D18) | a value shared in the graph is computed once, and nothing stale can survive a change of a variable |
| the tree evaluation kept, `flatEvaluation` | the reference of the flat one, bit for bit |
| `esym.Optimize` on the expressions, not in `FlatProgram::Build` (#3085) | the result can be looked at as expressions, and every user of a graph gains |
| `mergeDuplicates` a bool; leaves merged | merging the operands first compares any depth at no extra cost |
| level 1 exact and the default of `CreateSymbolicUserFunction` | the results of all test models stay the same |
| one structure, `GetFlatProgramData()`, behind every output; the formats `'Python'`, `'symbolic'`, `'numpy'`, `'sympy'`; other languages through sympy (#3087) | one writer per format, without Exudyn |
| `mod`, `round`, comparisons as Exudyn computes them in every format | the exported function computes what Exudyn computes |
| a copy of the recording per thread instead of a context through every node class (#2978) | no change of the evaluation of about 30 classes; the copy keeps the buffers of its nodes |
| `exudyn.symbolicUtilities` beside `exudyn.symbolic`; the result follows `functions` (#3069) | one function serves a Python and a symbolic user function |
