# tools/generators/ — the new generator code

Maintainer tools for the definition format of revision plan step 31. The six established generators
still live in `src/pythonGenerator/`; the code here grows as Phase 3 moves generation onto
[`definitions/`](../../definitions/README.md).

| file | what it does | used by |
|---|---|---|
| `definitionEmitter.py` | writes the old definitions out as `definitions/itemDefs*.py` and `structureDefs*.py`. It does not parse: the two old generators hand it the representation they already built | the two old generators, when `EXUDYN_EMIT_DEFINITIONS` is set |
| `emitDefinitions.py` | runs those two generators with `EXUDYN_EMIT_DEFINITIONS=1` | the maintainer, by hand |
| `outputVariableEmitter.py` | generates `src/Autogenerated/OutputVariableTypes.h` from `definitions/outputVariableTypes.py`, after checking the bit allocation | `src/pythonGenerator/autoGeneratePyBindings.py`, on every generation |

## Re-emitting the definitions

After editing `src/pythonGenerator/objectDefinition.py` or `systemStructuresDefinition.py`:

```
python tools/generators/emitDefinitions.py
python tools/regenerate.py --check
```

in `venvExuP313`. Emission is **off** unless `EXUDYN_EMIT_DEFINITIONS` is set, so a normal
generator run — and therefore `regenerate.py --check` — is unaffected by this directory.

A member that matches an entry of `definitions/itemFunctions.py` is emitted as
`ItemFunctionDef(...)`; if the library does not cover it, it is written out in full. After changing
the library, re-emit so the item files follow.
