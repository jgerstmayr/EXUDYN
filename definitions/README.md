The input of the code generators, in the format that replaces the line-based tables in
`src/pythonGenerator/objectDefinition.py` and `systemStructuresDefinition.py` (revision plan
step 31). The detail and the measurements behind every decision are in
[exudynRevisionLog2026.md](../docs/revision/exudynRevisionLog2026.md), step 31.

## Files

| file | written by | what it is |
|---|---|---|
| `definitionTypes.py` | hand | the single vocabulary: types, flags, destinations, default values, the member constructors, the function-library resolution |
| `itemFunctions.py` | hand | the function declaration library: one entry per shared declaration of a function that items override |
| `outputVariableTypes.py` | hand | the `OutputVariableType` registrator: names and bit positions, generates `src/Autogenerated/OutputVariableTypes.h` and the Python enum |
| `outputVariableDescriptions.py` | hand | the output-variable texts shared by four or more items |
| `itemDefsNodes.py`, `itemDefsObjects.py`, `itemDefsMarkers.py`, `itemDefsLoads.py`, `itemDefsSensors.py` | **emitted** | one `ItemDefinition(...)` per item |
| `structureDefs*.py` | **emitted** | one `StructureDefinition(...)` per settings / solver / system structure |

`definitionTypes.py` is grouped in three blocks by where a name is used: **SHARED** (types, default
values, sentinels), **ITEMS**, **STRUCTURES**.

## Members

```python
ItemParameter(type=TReal(minimum=0), destination=DestComp+DestParam, pythonName='physicsMass',
    defaultValue=0., description=r'$m$mass [SI:kg] of mass point')
ItemFunction(type=Tvoid, destination=DestComp, pythonName='ComputeContactForces',
    description='...', cFlags=CFConst, args='...')
ItemFunctionDef('ComputeODE2LHS')
ItemFunctionDef('GetNumberOfNodes', implementation='return 1;')
```

- `type`, `destination`, `pythonName`, `description` and — for parameters — `defaultValue` are
  **required**; a forgotten one raises during generation. Where a parameter genuinely has no
  default, write `defaultValue=NoDefaultValue`.
- Default values are real values (`True`, `0.`, `1e-8`); C++ constants and constructor calls are
  `CppValue`s (`DVInvalidIndex`, `DVDefaultColor`, `DVZeroVector3D`).
- A function with `implementation=None` is a declaration whose body is in the hand-written `.cpp`;
  `''` is an empty body. `isVirtual` defaults to `True`.

## The function library (`itemFunctions.py`)

An item does not restate a declaration it shares with other items: it writes
`ItemFunctionDef(name)` and the declaration comes from the library.

- An entry is found by the item's `classType`, its `cParentClass` and the function name. Both keys
  are **`None` unless the declaration really depends on them** — `sharedFunctions` holds the ones
  that are the same for every item type, then one list per item type; inside a list, entries with
  no parent first, then grouped by parent.
- Where a name is still not unique, the use site says which with `destination=`, `cFlags=` or
  `args=`. These default to `None`, so a forgotten one **raises and lists the alternatives**.
- `description=` at the use site overrides the library text. Use it only where the text is
  genuinely item-specific.
- Only functions that **override** a parent's virtual function belong in the library. Functions
  new in one item are written out with `ItemFunction(...)`.
- The library states what the C++ base headers (`src/System/CObject*.h`, `CNode*.h`, `CMarker*.h`,
  …) declare. **Change both together.** Plan step 32 turns that agreement into a check; until then
  it is kept by hand.
